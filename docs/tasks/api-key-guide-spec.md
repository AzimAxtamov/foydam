## 1. Цель и контекст

Получение API-ключа — **главный барьер конверсии** всей воронки. Всё, что до него
(виральная карточка → реф-переход → методика), работает вхолостую, если селлер здесь отвалится.

Барьер **не технический, а доверительный**: страх «зачем чужому боту доступ к моему магазину».
Отсюда порядок подачи: сначала безопасность, потом шаги.

**Гайд живёт ВНУТРИ бота** (сообщения + фото-скриншоты). Уводить на внешнюю ссылку в момент,
когда селлер уже почти сконвертировался, — терять его. Лендинг на foydam.uz — отдельная задача.

## 3. Сценарий гайда

**Шаг 0 — доверие (первое сообщение, до всяких шагов).**

Текст §5.1. Кнопки: `▶️ Показать, где взять ключ` (`guide:key:step1`).

**Шаги 1..N — инструкция.** Каждый шаг = отдельное сообщение: фото-скриншот + подпись
(1–2 строки). Кнопки: `◀️ Назад` / `▶️ Дальше`, на последнем шаге —
`✅ У меня есть ключ, подключить` (`onboard:token:start`).

Скриншоты: `assets/guide/key/{lang}/step{N}.png`, отправлять по `file_id` с кэшем в БД
(`guide_assets: key varchar, file_id varchar, lang varchar`) — повторные показы не перезаливают файл.
Если `file_id` нет — заливаем один раз и сохраняем.

✅ **Контент шагов подтверждён** (см. §5.2) — пути и названия полей взяты из живого кабинета,
не менять и не «улучшать». Страница ключей: `https://seller.uzum.uz/seller/api-keys`.
Скриншоты предоставляет Azim; значение ключа на скринах должно быть замазано.

**Факты о ключе (подтверждено кабинетом, 14.07):**
- Путь: «Мой профиль» (правый верхний угол) → «Ключи API» → «+ Создать ключ».
- Форма: **Название**, **Магазин** (мультиселект, можно все), **Разрешения** («Только чтение»),
  **Срок действия**. Все поля обязательные.
- **Ключ виден всегда** в таблице (колонка «Секретный ключ»), копируется в любой момент —
  предупреждения «показывается один раз» НЕ давать (это неправда).
- Uzum отключает ключи, попавшие в открытые источники → в тексте доверия предупредить о скринах.

**🔴 Срок действия: по умолчанию 1 МЕСЯЦ.** Главная мина фичи. Селлер, пролиставший форму,
получит ключ, который умрёт через 30 дней; синк начнёт молча падать в 401, отчёты замрут,
а виноватым будет бот. Требования:
- в гайде смена срока на «Неограниченный» — обязательный подсвеченный пункт (наравне с правами);
- фоновый синк на 401: пометить токен невалидным, **уведомить селлера один раз**
  («Uzum перестал принимать ваш ключ — истёк срок или ключ отозван») + кнопка `🔑 Подключить заново`;
- не спамить: одно уведомление на переход валиден→невалиден; повторные 401 молча.

**🔴 Два разных 403 — не смешивать.** `GET /v1/shops` возвращает **все** магазины кабинета,
включая те, на которые ключ НЕ выдан; запрос данных по такому магазину → 403.
| Причина 403 | Что показать селлеру |
|---|---|
| магазин не входит в scope ключа | «Ключ выдан не на все магазины. Пересоздайте ключ, отметив все магазины» + кнопка в гайд |
| магазин неактивен в Uzum | «Магазин неактивен, отчёт по нему невозможен» |

Различать по факту: после подключения **пробить каждый shopId одним лёгким запросом** и сохранить
флаг доступности; магазины вне scope — отдельный список в UI. Если тело 403 не позволяет отличить
причины — [AZIM] сравнить ответы на неактивном магазине и на магазине вне scope, дописать сюда.

**Мультимагазин:** ключ покрывает выбранные магазины (можно все) → отдельный флоу «второй ключ»
НЕ нужен. В отчёте показывать «магазинов подключено: N», при N < числа магазинов из `/v1/shops` —
подсказка про пересоздание ключа.

**[AZIM] Мелочи, не блокирующие разработку:** есть ли лимит на число активных ключей;
может ли ключ создать менеджер магазина или только владелец.

**Финал — подключение.** `onboard:token:start` → существующий флоу ввода токена.

## 4. Приём ключа (ужесточение существующего флоу)

- **Только личка.** Если сообщение с ключом пришло из группы/канала — не обрабатывать,
  ответить одной строкой «Ключ можно присылать только в личный чат с ботом» и, если есть права,
  удалить сообщение.
- **Мгновенное удаление** сообщения с ключом (`deleteMessage`) — сразу после чтения, до валидации.
  Если удалить не удалось (нет прав/устарело) — сказать селлеру, чтобы удалил вручную.
- **Никогда не логировать** значение ключа и не класть в exception message. В логах — только
  `sellerId`, длина, результат валидации.
- Валидация формата **до** обращения к API (trim, обрезать случайно скопированный `Bearer `,
  проверить на непечатаемые символы) → затем `GET /v1/shops` как проверка боем.
- Шифрование AES at rest (существующий механизм `api_tokens`).
- Успех → сообщение со списком найденных магазинов + запуск синка + «отчёт будет готов через ~N мин».
- **Неактивные магазины:** `/v1/shops` их отдаёт, а product/finance по ним → 403 «Shop is not available».
  Фильтровать, сырую ошибку селлеру не показывать (см. FOYDAM-CONTEXT §4).

### 5.2 Шаги (контент подтверждён скриншотами кабинета, 14.07)

```
Шаг 1. Откройте seller.uzum.uz. В правом верхнем углу нажмите «Мой профиль» → «Ключи API».
        (Магазин выбирать не нужно — пункт доступен из любого экрана.)

Шаг 2. На странице «Ключи API» нажмите «+ Создать ключ».

Шаг 3. Заполните форму:
        • Название — любое, например «Foydam» (так ключ легко найти и отозвать).
        • Магазин — выберите ВСЕ свои магазины (можно отметить несколько).
          Если магазин не отмечен, отчёта по нему не будет.
        • Разрешения — «Только чтение». ⚠️ Такой ключ физически не может изменить
          ничего в вашем магазине.
        • Срок действия — поменяйте на «Неограниченный».
          ⚠️ По умолчанию стоит 1 месяц! Если оставить, через месяц ключ перестанет
          работать и отчёты остановятся.
        Нажмите «Создать ключ».

Шаг 4. Ключ появится в таблице, в колонке «Секретный ключ» — скопируйте его целиком.
        Он остаётся виден всегда, так что потерять его нельзя.

Шаг 5. Пришлите ключ сюда одним сообщением. Бот удалит его из чата сразу после проверки.
```

⚠️ Порядок менять нельзя: права и срок выбираются ДО создания ключа. Оба поля — «нескипаемые»:
на скриншоте шага 3 подсветить и «Разрешения», и «Срок действия».

**Скриншоты (есть у Azim):** step1 = меню «Мой профиль» с подсвеченным «Ключи API»;
step2 = страница «Ключи API» с кнопкой «+ Создать ключ»; step3 = модалка «Создать ключ»
(стрелки на «Магазин», «Разрешения = Только чтение», «Срок действия = Неограниченный»);
step4 = таблица ключей с колонкой «Секретный ключ» — **значение ключа на скрине замазать**.

### 5.3 Ошибки (RU)

- Ключ не принят Uzum (401/403): «Uzum не принял этот ключ. Чаще всего это опечатка при
  копировании или ключ уже отозван. Скопируйте заново целиком, без пробелов.»
  Кнопки: `🔑 Показать инструкцию` / `🔁 Попробовать снова`.
- Похоже на не-ключ (короткая строка, ссылка, телефон): «Это не похоже на API-ключ.
  Он выглядит как длинная строка из букв и цифр.» + `🔑 Показать инструкцию`.
- Uzum недоступен (5xx/таймаут): «Uzum сейчас не отвечает. Ключ сохранён, повторю проверку
  автоматически.» — не терять селлера из-за их аптайма.

## 6. Метрики воронки

Таблица `funnel_events` (или расширение `share_events` до общего вида — на усмотрение):
`seller_id, event varchar, created_at`.

События: `guide_opened`, `guide_step_N`, `guide_finished`, `key_submitted`, `key_invalid`,
`key_valid`, `report_delivered`.

Это замер **главного барьера**: `guide_opened → key_valid` — та самая конверсия, ради которой
всё строится. Отвал по шагам покажет, какой именно шаг гайда непонятен.

Админ-команда `/stats_funnel` — числа за 7/30 дней (nice-to-have).
